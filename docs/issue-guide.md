# Issue Guide

작업은 Issue 생성으로 시작합니다.

## Issue Title

형식:

```text
[SCOPE] type: 작업 요약
```

예시:

```text
[FE] feature: 로그인 페이지 구현
[BE] feature: 사용자 API 구현
[BE] fix: 토큰 만료 시 재로그인 처리
[COMMON] docs: README 실행 방법 추가
```

## Scopes

- `fe`: 프론트엔드 작업
- `be`: 백엔드 작업
- `common`: 공통 설정, 문서, GitHub 템플릿, 레포 관리 작업

Issue 제목에서는 scope를 대문자로 작성합니다.
작업 요약은 한글로 작성합니다.

- `FE`: 프론트엔드 작업
- `BE`: 백엔드 작업
- `AI`: AI 작업
- `COMMON`: 공통 설정, 문서, GitHub 템플릿, 레포 관리 작업

## Issue Content

Issue에는 아래 내용을 포함합니다.

- 작업 목적
- 구현 범위
- 완료 조건
- 참고 자료 또는 화면

### Checklist Format

Issue 본문의 실행 항목은 반드시 체크리스트로 작성합니다.

- `작업 목적`, `구현 범위`, `완료 조건`, `참고 자료 또는 화면` 구조를 유지합니다.
- 실행·검증·문서화 항목은 일반 하이픈 목록 대신 `- [ ] 항목`으로 작성합니다.
- 완료한 항목만 `- [x] 항목`으로 표시하고, 미완료·검토 필요 항목은 `- [ ] 항목`으로 남깁니다.
- 구현하지 않는 항목은 `범위 제외` 또는 `운영 전 확인` 아래에 `- [ ]`로 분리해 기록합니다.
- 체크 상태를 코드·테스트·문서 근거와 함께 갱신합니다. 확인되지 않은 항목을 임의로 `[x]` 처리하지 않습니다.

기본 형식:

```markdown
## 작업 목적
작업이 필요한 이유를 작성합니다.

## 구현 범위
- [ ] 구현 항목
- [ ] 검증·권한·오류 처리 항목
- [ ] API 명세·체크리스트 갱신

## 완료 조건
- [ ] 관련 테스트 통과
- [ ] 문서와 구현 상태 일치

## 참고 자료 또는 화면
- [ ] 관련 Issue·PR·문서·화면
```
