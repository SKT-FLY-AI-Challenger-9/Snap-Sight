> 문서 상태: 초안 (팀 리뷰 전) — 일부만 확정 가능, 나머지는 의도적으로 미정

## 목적

Document C~E에서 반복적으로 "6단계로 미룸"이라 표시해온 질문 — 여러 축이 동시에 어긋났을 때 어떻게 처리할지 — 을 정리한다.

**cothe-baek 확인(2026-08-14) 이후 상황이 바뀌었다: 지금 구현 범위에서는 이 문제 자체가 거의 발생하지 않는다.** 현재 활성화된 신호는 "탐지 실패(LOST/AMBIGUOUS 합침)"와 "수평 편차(dx)" 둘뿐이고, 이 둘은 애초에 동시에 존재할 수 없다 — 탐지가 안 되면 dx 자체가 계산되지 않기 때문이다. 즉 지금은 매 순간 "탐지 실패" 또는 "dx 기반 판정(LEFT/RIGHT/READY)" 중 하나만 존재하고, 겹칠 축이 없다.

그래서 이 문서는 지금 당장 쓰일 규칙표가 아니라, **수직(dy)이나 거리(CLOSER)가 나중에 활성화됐을 때를 대비한 원칙**으로 성격이 바뀐다. 아래 원칙들은 미래를 위해 정의해두는 것이고, 지금 구현에 즉시 필요한 건 아니다.

## 확정 가능한 원칙

### 원칙 1: 탐지 축이 구조적으로 최우선이다

Document C에서 정리한 이유 그대로다 — 탐지가 안 되면 수평·거리 정보 자체가 의미가 없다. 이건 어떤 연구 근거보다는 **논리적 필요조건**에 가깝다. LOST 또는 AMBIGUOUS 상태일 때는 수평/READY 관련 피드백보다 탐지 축 피드백을 우선한다.

**현재 적용 여부**: 지금은 탐지 실패 시 dx 자체가 계산되지 않으므로, 이 원칙이 실제로 시험되는 상황이 없다(둘이 애초에 동시에 존재 불가). dy가 추가되면 "탐지 실패 vs dx 유효 vs dy 유효"의 조합이 생기므로 그때부터 실질적으로 적용된다.

단, LOST와 AMBIGUOUS가 서로 다른 취급을 받아야 하는지는 지금은 하나로 합쳐 처리하기로 확인됐으므로(Document D), 당장은 하위 규칙으로 나눌 필요가 없다.

### 원칙 2: 탐지된 상태에서, 사운드 채널은 결합 메시지를 우선 검토한다

Document A 핵심 발견 3, Document B 원칙 4의 재적용이다. 수평 축이 허용 범위를 벗어났을 때(향후 거리·수직 축이 추가되면 그것까지), 우선순위로 하나만 골라 보여주기보다 한 메시지에 결합해서 전달하는 방식을 기본으로 검토한다. 이 근거는 **음성 채널에 한정**된다 (EasySnap, PortraitFramer 모두 음성 사례).

**현재 적용 여부**: 지금은 결합할 두 번째 축이 없어(수평 하나뿐) 적용 시나리오가 없다. dy가 피드백에 반영되는 순간부터 "수평+수직 결합 메시지"가 실제로 필요해진다 — dy 반영 시 이 원칙부터 먼저 재검토해야 한다.

### 원칙 3: 햅틱 채널의 결합 여부는 별도 검증 대상이다

Document A/B에서 이미 확인된 사실의 재확인이다. 진동 모터 1개로 여러 축을 동시에 표현하는 방법은 어느 선행연구에도 없다. "가장 우선순위 높은 축 하나만 표현"과 "결합 패턴 시도" 두 후보 모두 열어두고, 원칙으로 확정하지 않는다.

**현재 적용 여부**: 원칙 2와 같은 이유로 지금은 적용 시나리오가 없다.

## 아직 정의할 수 없는 것

- **수평+거리 동시 편차 처리**: CLOSER 자체가 미구현이라 조합 규칙을 만들 수 없다 (여전히 미해결)
- **수평+수직 동시 편차 처리**: dy가 아직 피드백에 반영되지 않아 조합 규칙을 만들 수 없다 (신규 미해결 항목, CLOSER보다 먼저 필요해질 가능성 있음)
