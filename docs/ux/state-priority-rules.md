# 동시 상태 결합·우선순위 규칙 (초안)

> 문서 상태: 초안 (팀 리뷰 전) — 일부만 확정 가능, 나머지는 의도적으로 미정
> 관련 이슈: #5 [FE] 접근성 UX 및 햅틱·사운드 피드백 인터페이스 정의
> 선행 문서: docs/research/blind-camera-ux-notes.md, docs/ux/design-principles.md, docs/ux/capture-states.md, docs/interfaces/cv-to-ux-interface-draft.md, docs/ux/feedback-mapping.md

## 목적

Document C~E에서 반복적으로 "6단계로 미룸"이라 표시해온 질문 — 여러 축이 동시에 어긋났을 때 어떻게 처리할지 — 을 정리한다.

**`docs/deviation-interface.md`(v0.1) 확정으로 우선순위가 다시 높아졌다.** 이 계약은 `x_deviation`(수평)과 `size_deviation`(거리)을 **동시에** 출력한다 — 즉 "탐지됨 + 수평 어긋남 + 거리 어긋남"이 한 프레임에서 동시에 발생할 수 있는 구조다. 이전에 "겹칠 축이 없다"고 판단했던 전제(거리 축 미구현)가 깨졌으므로, 이 문서의 원칙들은 이슈 #29 완료 시점부터 바로 필요해진다.

## 확정 가능한 원칙

### 원칙 1: 탐지 축이 구조적으로 최우선이다

Document C에서 정리한 이유 그대로다 — 탐지가 안 되면 수평·거리 정보 자체가 의미가 없다. 이건 어떤 연구 근거보다는 **논리적 필요조건**에 가깝다. LOST 또는 AMBIGUOUS 상태일 때는 수평/READY 관련 피드백보다 탐지 축 피드백을 우선한다.

**현재 적용 여부**: `subject_detected=false`일 때 `x_deviation`/`size_deviation` 모두 None이 되도록 계약에 명시되어 있어(`docs/deviation-interface.md`), 탐지 실패와 나머지 축은 여전히 동시에 존재하지 않는다. 다만 탐지된 상태에서는 `x_deviation`과 `size_deviation`이 동시에 유효할 수 있어, 원칙 2·3이 실질적으로 적용된다.

단, LOST와 AMBIGUOUS가 서로 다른 취급을 받아야 하는지는 지금은 하나로 합쳐 처리하기로 확인됐으므로(Document D), 당장은 하위 규칙으로 나눌 필요가 없다.

### 원칙 2: 탐지된 상태에서, 사운드 채널은 결합 메시지를 우선 검토한다

Document A 핵심 발견 3, Document B 원칙 4의 재적용이다. 수평 축이 허용 범위를 벗어났을 때(향후 거리·수직 축이 추가되면 그것까지), 우선순위로 하나만 골라 보여주기보다 한 메시지에 결합해서 전달하는 방식을 기본으로 검토한다. 이 근거는 **음성 채널에 한정**된다 (EasySnap, PortraitFramer 모두 음성 사례).

**현재 적용 여부**: `x_deviation`과 `size_deviation`이 이슈 #29 완료 시 동시에 제공되므로, "수평+거리 결합 메시지"가 곧 실제로 필요해진다.

### 원칙 3: 햅틱 채널의 결합 여부는 별도 검증 대상이다

Document A/B에서 이미 확인된 사실의 재확인이다. 진동 모터 1개로 여러 축을 동시에 표현하는 방법은 어느 선행연구에도 없다. "가장 우선순위 높은 축 하나만 표현"과 "결합 패턴 시도" 두 후보 모두 열어두고, 원칙으로 확정하지 않는다.

**현재 적용 여부**: 원칙 2와 같은 이유로 곧 적용 시나리오가 생긴다.

## 아직 정의할 수 없는 것

- **수평+거리 동시 편차 처리**: `x_deviation`/`size_deviation` 계약은 확정됐으나, 실제 값을 받아보기 전까지는 구체적인 조합 규칙(결합 메시지 문구 등)을 확정할 수 없다 (이슈 #29 완료 대기)
- y축 편차 처리: 계약 v0.2 예정, 그전까지 보류
