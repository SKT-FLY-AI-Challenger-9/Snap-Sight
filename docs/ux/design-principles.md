# Snap-Sight UX 설계 원칙 (초안)

> 문서 상태: 초안 (팀 리뷰 전)
> 관련 이슈: #5 [FE] feature: 접근성 UX 및 햅틱·사운드 피드백 인터페이스 정의
> 선행 문서: docs/research/blind-camera-ux-notes.md

## 목적

Document A에서 정리한 "확인된 사실 / 우리의 해석 / 검증할 가설"을
Snap-Sight에 적용할 UX 설계 원칙으로 압축한다.

이 문서는 사용자에게 촬영 상태를 어떻게 전달할 것인지에 대한 방향을 다루며,
③↔⑥ 데이터 계약의 구체적인 필드명·수치·프로토콜은 정의하지 않는다.

## UX 설계 원칙

1. **[근거 있음, 구체적 방식은 추정]**
   사용법 안내는 촬영 중 반복하기보다 세션 시작 전에 간결하게 제공하고,
   촬영 중에는 현재 행동에 필요한 안내에 집중한다.

2. **[근거 있음, 해결방식은 추정]**
   앱 자체 음성 피드백과 TalkBack이 동시에 발화하여 사용자의 인지를 방해하지 않도록
   피드백 채널과 타이밍을 설계한다.

3. **[추정]**
   촬영 피드백은 무제한 상시 신호보다 사용자가 인지할 수 있는 단위로 갱신하는 방향을
   우선 검토하되, 연속 신호와 이산 갱신 중 적절한 방식은 프로토타입에서 비교한다.

4. **[근거 있음, 음성 한정]**
   동시에 여러 축의 편차가 존재할 경우,
   음성에서는 관련 정보를 하나의 결합 메시지로 전달하는 방식을 우선 고려한다.

5. **[추정, 근거 거의 없음]**
   거리/크기 편차를 `CLOSER`와 같은 행동 지시 상태로 변환할지는
   현재 원칙으로 확정하지 않고 별도로 검증한다.

6. **[근거 있음, 구현 방식은 추정]**
   사용자와 사용 상황에 따라 피드백 채널 선호가 다를 수 있으므로
   음성·사운드·햅틱의 선택 또는 조절 가능성을 고려한다.

## 원칙으로 격상하지 않은 것

- 햅틱+사운드를 항상 동시에 제공한다는 전제
- 정확한 피드백 갱신 주기
- 진동 강도 및 패턴
- `LEFT / RIGHT / CLOSER / READY / TARGET_LOST`의 최종 상태 구성

위 항목은 이후 프로토타입 및 팀 논의를 통해 검증한다.

## 이 문서에서 다루지 않는 것

- 촬영 상태의 구체적인 구조
- ③↔⑥ 데이터 계약
- 상태별 햅틱·사운드·음성 매핑
- 동시 상태의 결합·우선순위·충돌 처리 규칙
