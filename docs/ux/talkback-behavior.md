> 관련 이슈: #5
> 선행 문서: docs/research/blind-camera-ux-notes.md (①), docs/ux/design-principles.md (원칙 2)

## 목적

Document B 원칙 2("앱 자체 음성과 TalkBack이 동시에 말하지 않게 설계")를 실제 동작 수준으로 구체화한다.

## 기본 동작 (제안)

1. **온보딩/설정 화면**: 일반 접근성 표준을 따른다 — 모든 버튼·요소에 contentDescription을 제공하고, TalkBack만으로 전체 탐색이 가능해야 한다. [일반 원칙]
2. **촬영 세션(실시간 피드백 구간)**: 앱 자체 음성·사운드가 주 채널이 되는 동안, TalkBack이 같은 화면 요소를 동시에 읽지 않도록 한다. [Document A ① 근거 — 중첩 시 인지 혼란이 관찰됨]
3. **상태 전환 안내**: 화면이 바뀌거나(대기 → 촬영 세션 등) 중요한 이벤트가 발생하면 TalkBack 사용자에게도 그 사실이 전달돼야 한다. [추정 — 구체적 구현 방법 미정]

## 아직 결정하지 않은 것

- 실제 구현 방법 (TalkBack을 일시적으로 비활성화할지, 화면 구조 설계로 자연히 겹치지 않게 할지 등)
- 촬영 세션 중 TalkBack을 완전히 끌지, 겹치지만 않게 타이밍만 조율할지 — Document D에서 지적했듯, ①의 연구 근거는 "중첩되면 혼란"까지만 확인했지 "꺼야 한다"는 걸 뒷받침하지 않는다. 같은 이유로 여기서도 "비활성화"를 기본값으로 정하지 않는다
