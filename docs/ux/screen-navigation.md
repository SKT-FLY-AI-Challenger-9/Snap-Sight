> 문서 상태: v2 — 2026-08-22, #84 구현(PR #85) 반영 개정. 기획 시점 원문(v1, 2026-08-21)은 git 이력 참고
> 관련 이슈: #84 [FE] 화면 전환·조작 문법(tap-first)
> 선행 문서: docs/screen-design.md, docs/ux/accessibility-guidelines.md, docs/ux/design-principles.md, docs/ux/feedback-mapping.md, docs/research/blind-camera-ux-notes.md
> 구현 정본: `frontend/.../ux/TapGrammar.kt`(제스처 감지), `MainActivity.kt`(화면별 배선·복귀 경로), `ux/GuidanceFeedback.kt`(전환 earcon)

## 이 문서의 역할 (v2에서 달라진 점)

v1은 기획안이었다. #84로 P1이 구현·머지되면서 이 문서는
**① 확정된 문법의 기록, ② 기획 대비 달라진 결정과 그 리스크, ③ 남은 작업, ④ 사후 검증 항목**
을 담는 문서로 성격이 바뀐다. 기획의 배경 논리(왜 볼륨 버튼을 내리는가, as-is 문제 5가지)는
v1과 동일하므로 여기서는 요약만 남긴다 — 상세는 git 이력의 v1 참고.

배경 요약: 볼륨 버튼은 셔터 순간의 흔들림·위치 탐색 비용·짧게/길게 오버로딩 문제가 있었고,
선행연구(②·④·⑤)도 모두 터치 기반이었다. 또한 시스템 뒤로가기가 앱 종료로 이어지고,
화면 전환 확인 신호가 전무하며, 복귀 문법이 화면마다 달랐다.

## 1. 확정된 전역 문법 (구현 기준)

**세 문법**: 화면 아무 곳 **두 번 탭 = 그 화면의 메인 기능**, **세 번 탭 = 서브 기능**,
**길게 누르기(≈0.5초)·시스템 뒤로가기 = 복귀**. 한 번 탭은 버튼 등 일반 터치 UI 몫으로
남기며, 자식 컴포저블이 소비한 탭은 전역 문법이 건드리지 않는다 (`TapGrammar.kt`).

| 화면/상태 | 두 번 탭 (메인) | 세 번 탭 (서브) | 길게 누르기 / 뒤로가기 (복귀) |
|---|---|---|---|
| 온보딩 | 권한 허용 | 작동 방식 낭독 | 없음 (첫 화면) |
| 홈 | 세션 시작 | 사진 찾기 열기 | 1회차 "한 번 더 누르면 앱을 종료합니다" → 2초 내 재입력 시 종료 |
| 세션 (LISTENING~AIMING) | 발화 종료 / **셔터** | 현재 상태+안내 문구 낭독 | 세션 취소 → 홈 |
| 결과 | 다시 촬영 | 설명 다시 듣기 | 닫기 — "사진은 저장됐어요. 홈입니다" |
| 설정 | 현재 설정값 요약 낭독 | 안내 방식 설명 낭독 | 홈 (서버 주소 적용 포함 — 버튼·제스처·뒤로 모두 `leaveSettingsToHome()` 공통 경로) |
| 사진 찾기 | 말해서 찾기 | 결과 듣기 | 홈 (검색 필터 초기화) |

- 볼륨 버튼 핸들러는 **삭제**됐다. 볼륨 키는 시스템 볼륨으로 환원 — 사운드·TTS 크기 조절이
  자연스러워지는 부수 효과. 모든 안내 문구도 "볼륨 버튼을 눌러" → "화면을 두 번 탭해"로 교체됨.
- TalkBack 경로: 조준 중 미리보기 전체가 "촬영" 접근성 노드(`CaptureScreen.onShutterTap`) —
  TalkBack의 표준 두 번 탭도 셔터로 수렴한다.
- 전환 확인: 위성 화면 진입 시 상승 2음 earcon+진동+TTS 1회("설정 화면입니다" — **첫 진입에만**
  버튼 위치 상세를 덧붙이고 재진입부터는 이름만, 앱 실행 단위 `visitedScreens`), 홈 복귀 시
  하강 2음+진동+"홈입니다" (`GuidanceFeedback.playScreenEnter/Exit`).

## 2. 기획(v1) 대비 달라진 결정

### 2-1. "문법 2개"가 3개가 됐다 — 세 번 탭(서브) 추가

v1은 연구① "상호작용 횟수 적게" 근거로 "두 번 탭=진행 / 길게·뒤로=복귀" 2문법이었다.
구현 과정에서 "한 번 탭=메인, 두 번 탭=뒤로, 세 번 탭=서브" 배치를 시도했다가(7ab1e6e)
한 번 탭이 일반 터치 UI와 충돌해 회귀했고, 최종적으로 **두 번/세 번/길게** 3문법으로
확정됐다(943b302).

- **얻은 것**: 화면마다 두 번째 기능(상태 낭독, 설명 듣기, 결과 듣기)에 버튼 탐색 없이 접근.
- **비용 1 — 학습 부담**: "문법 2개만" 원칙과 긴장 관계. 세 번 탭은 온보딩·진입 안내에서
  적극적으로 알려주지 않으면 발견되지 않는 기능이 될 수 있다. [사후 검증 1]
- **비용 2 — 셔터 지연**: 세 번 탭을 기다리느라 두 번 탭은 `doubleTapTimeout`(약 300ms) 뒤에
  확정된다(`TapGrammar.kt` 주석). 즉 **셔터가 두 번째 탭에서 약 0.3초 늦게 터진다.**
  조준이 완성된 순간을 잡는 앱 특성상 무시할 수 없는 지연 — 다만 `RingFrameBuffer`가
  트리거 전후 1초를 들고 있어 실질 피해는 프레임 선택으로 상쇄될 수 있다. [사후 검증 2]

### 2-2. 볼륨 버튼을 즉시 제거했다 — 단계적 전환(병행→검증→제거) 생략

v1의 4-2는 병행 기간을 두고 탭 사용률·오조작률을 로그로 비교한 뒤 제거하는 계획이었다.
구현은 이를 생략하고 943b302에서 핸들러를 바로 삭제했다.

- 물리 버튼 선호 사용자(연구① 선호 다양성)의 이탈 여부를 이제 **사전 비교가 아니라
  사후 관찰로만** 확인할 수 있다. v1의 검증 가설 중 "볼륨 대비 비교" 항목들은
  아래 5절에서 사후 검증 항목으로 재편했다. [사후 검증 3]

## 3. 구현 현황

### 완료 (P1, #84 / PR #85)

- [x] 설정의 서버 주소 적용을 복귀 공통 경로로 이동 (뒤로 제스처로 나가도 적용됨)
- [x] 전환 확인 2채널 — 진입/복귀 earcon 2종+진동, 진입·복귀 TTS 1회(첫 진입만 상세)
- [x] 조준 미리보기의 TalkBack "촬영" 노드
- [x] 안내 문구 전면 교체 (환영·AIMING·ERROR·온보딩)
- [x] 볼륨 핸들러 삭제, 시스템 볼륨 환원

### 미구현 잔여

- [ ] **시각 헤더** (v1 4-3의 3번째 채널) — 위성 화면 상단 대형 헤더+배경 톤. 잔존시력
  사용자용 채널이 아직 빠져 있어, 현재 전환 확인은 청각·촉각 2채널뿐이다. (P2)
- [ ] **배치 문법 통일** (v1 4-4) — 홈 설정 진입은 여전히 우상단 소형 칩, 사진 찾기 복귀는
  좌상단 ‹, 최하단 전폭 복귀 버튼 없음. 탭 문법이 생겨 긴급도는 내려갔지만, 제스처를
  모르는 사용자의 대체 경로(원칙 5)로서 여전히 필요하다. (P2)
- [ ] **결과 화면 진입 직후 출구 안내** (v1 4-5) — `showResultScreen()`에 출구 안내 TTS 없음.
  자동으로 나타난 화면인데 "다시 찍으려면 두 번 탭, 끝내려면 길게"를 말해주지 않는다. (P2)
- [ ] **얼굴 등록 문맥 복원** (v1 4-5) — 점프 예고 TTS는 구현됐으나, 등록 종료 후 설정으로
  자동 복귀하지 않고 카메라 화면에 남는다 (`startFaceEnrollment`). (P3)
- [ ] 온보딩·홈 첫 안내에 세 번 탭(서브 기능) 소개 추가 — 2-1의 발견성 문제 대응. (P2)

## 4. 유지되는 설계 원칙 (v1에서 승계)

1. 허브&스포크, 깊이 1 고정 — 새 화면·중간 단계를 추가하지 않는다.
2. 한 번 탭은 일반 터치 UI 몫 — 온스크린 버튼은 제거하지 않는다.
   [근거 있음 — WCAG 2.5.7 취지, accessibility-guidelines §2 "터치 컨트롤을 없애지 않는다"]
3. 전환 TTS는 1회만 (feedback-mapping TTS 정책), 첫 진입에만 상세.
   [근거 있음 — 연구① 요구 2, design-principles 원칙 1]
4. 자동 전환은 예고·복원 — 결과 자동 닫힘은 도입하지 않는다(촬영 주체성).
5. 세션 중 홈 오버레이 유지 구조(LISTENING/PARSING) — 전환 횟수를 줄이는 설계로 유지.

## 5. 사후 검증 항목 (구현이 앞섰으므로 실사용 관찰로 확인)

1. **세 번 탭 발견성** — 안내 없이도 서브 기능을 찾아 쓰는가. 못 찾으면 온보딩 소개(3절)로
   보완하고, 그래도 사용률이 바닥이면 세 번 탭 축소를 논의한다.
2. **셔터 300ms 지연 체감** — doubleTapTimeout 대기가 "탭했는데 안 찍힌다"로 느껴지는지.
   느껴진다면 AIMING 한정으로 두 번 탭 즉시 확정(세 번 탭 포기) 같은 화면별 예외를 검토.
3. **볼륨 버튼 부재 반응** — 물리 버튼을 찾는 사용자 비율. 높으면 옵션(설정)으로 부활 검토.
4. 빈 영역 두 번 탭과 버튼 단일 탭의 공존이 오조작 없이 학습되는가.
5. 진입/복귀 earcon(상승/하강) 은유가 학습 없이 전달되는가.
6. 홈 2회 뒤로 종료의 안내 문구·2초 대기가 적절한가.
7. 전환 TTS가 TalkBack 낭독과 겹치지 않는가 (talkback-behavior.md 미결 쟁점과 동일).

## 이 문서에서 다루지 않는 것

- 조준 피드백(방향 안내 햅틱·사운드·TTS) — feedback-mapping 개정판 유지
- earcon 음형·햅틱 수치, 탭 판정 시간 튜닝 — 프로토타입/실사용 데이터로 조정
- 사진 찾기·설정 화면 내부 기능 개편 — 각 담당 이슈 몫
